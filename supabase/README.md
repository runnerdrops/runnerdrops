# RunnerDrops — Supabase backend

## Files

| Path | What |
|---|---|
| `migrations/0001_schema.sql` | Tables, enums, views, row-level security, and the `subscribe()` sign-up RPC. |
| `seed.sql` | The September 2026 mockup content as rows: 20 brands, 20 shoes, 21 calendar releases, ratings, the HYROX list. Generated by `python3 ../tools/make_seed.py > seed.sql`. |

## Shape

```
brands ─┬─ shoes ─┬─ colorways
        │         ├─ releases ──── release_retailers ─── retailers
        │         ├─ price_history
        │         ├─ reviews ──── review_sources        (02 Reviewers)
        │         ├─ runner_votes                        (03 Runners)
        │         ├─ shoe_ratings                        (01 RunnerDrops + the two aggregates)
        │         └─ list_entries ─── lists              ("Best for …")
        └─ follows ─── subscribers ─── sms_messages      (private)
```

- `v_calendar` is what the Calendar and This Week pages read: one row per dated event, with brand, shoe, colorway, image and retailer links already joined.
- `v_shoe_cards` is what the Shoes grid and brand lineups read.
- Everything under `subscribers` has **no public policy**: only the service role (server-side / edge functions) can read or write it. The site signs people up through `subscribe(phone, brands[], shoes[], categories[], restocks, source)`, which is the only write the anon key can make.
- Images are referenced by storage path (`shoes/NIKE_SQ.jpg`, `logos/nike.png`) in a public bucket called `media`.

## Applying

Through the Supabase connector in Claude, or manually: SQL Editor → paste `migrations/0001_schema.sql` → Run, then `seed.sql`.
